# 聚合页案例格式说明统一设计

## 目标

将“按院校”“按专业”“查看经验”三个聚合页的格式说明统一为“所有案例”页面已经采用的独立文案结构：先说明页面用途与排序规则，再单独使用“案例格式：……”展示条目字段。

本次只统一说明文案的结构和措辞，不改变案例列表内容、详情链接、排序规则、评价正文或页面样式。

## 当前结构

站点由 MkDocs 构建，`scripts/build_cases.py` 负责生成以下页面：

- `docs/cases/by-university.md`；
- `docs/cases/by-major.md`；
- `docs/experience.md`。

三个页面目前都把用途、条目格式和排序说明合并在同一段中，并使用“格式为”描述字段；“所有案例”页面则已经将格式说明独立为：

```text
案例格式：`昵称 | 高考年份 | 高考分数 | 院校 | 专业`。
```

## 方案选择

采用“用途/排序说明”和“案例格式”分段展示的方案。该方案保留现有信息，同时让三个聚合页与“所有案例”的格式说明在文案层级、前缀和 Markdown 行内代码样式上保持一致。

不采用以下方案：

- 仅在原句中把“格式为”替换为“案例格式”，因为格式说明仍与其他信息挤在同一段，视觉层级没有统一；
- 删除用途或排序说明，只保留格式，因为会丢失现有页面信息。

## 文案规格

### 按院校

```markdown
展示**院校评价**的聚合结果。院校按拼音排序。

案例格式：`昵称 | 专业：评价`。
```

### 按专业

```markdown
展示**专业评价**的聚合结果。专业按拼音排序。

案例格式：`昵称 | 院校：评价`。
```

### 查看经验

```markdown
本页汇总所有已收录案例的 **给学弟学妹的建议**。排序不分先后。

案例格式：`昵称 | 高考分数 | 院校 | 专业：评价`。
```

## 界面与范围

- 目标平台：Web，沿用当前 MkDocs Material 页面结构。
- 美学方向：延续现有教育手册的编辑式排版，不重新设计页面。
- 色彩与字体：完全继承当前主题，不新增 CSS、颜色或字体。
- 布局：保持左对齐信息流；仅增加说明段与格式段之间的一个空行。
- 不修改三个页面的标题、分组标题、列表项、链接或空状态。
- 不修改“所有案例”或案例详情页。

## 数据流与实现边界

1. 投稿表格和案例元数据继续按现有流程读取。
2. `scripts/build_cases.py` 继续构建院校、专业和经验聚合内容。
3. 只调整三个生成区块开头的固定 Markdown 文案和空行。
4. 重新运行生成器，将相同文案写入三个生成页面。
5. 不改变聚合数据结构、相对链接、排序函数或案例 URL。

## 测试与验收

采用测试先行：

1. 更新生成器测试，断言三个页面分别包含准确的用途/排序说明和独立“案例格式”段落。
2. 先运行测试并确认它因当前文案仍在同一段而失败。
3. 修改生成器中的三处固定文案，使测试通过。
4. 重新生成站点内容，确认生成差异只涉及三个目标页面的说明段落。
5. 运行完整自动测试和 `mkdocs build --strict`。
6. 在浏览器打开三个目标页面，确认说明分段正确、列表链接和正文正常、控制台无新增错误。

## 不在本次范围内

- 不改变格式字段本身或增加高考年份；
- 不改变列表内容、链接范围、评价正文或排序；
- 不调整“所有案例”、详情页或其他聚合页；
- 不新增 CSS、JavaScript、依赖或路由；
- 不发布或部署站点。
