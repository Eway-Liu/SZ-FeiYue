# 聚合页案例详情链接设计

## 目标

让用户在“按院校”“按专业”和“查看经验”页面中，点击每条记录开头的加粗人物信息即可进入该记录对应的案例详情页。

评价正文继续作为普通文本展示，不扩大链接点击区域。昵称为 `Anonymous` 或 `Null` 的案例与其他案例行为一致，也可以进入其各自的详情页。

## 当前结构

站点由 MkDocs 构建。`scripts/build_cases.py` 从投稿数据生成：

- `docs/cases/case-<hash>.md`：案例详情页；
- `docs/cases/by-university.md`：按院校聚合页；
- `docs/cases/by-major.md`：按专业聚合页；
- `docs/experience.md`：经验聚合页。

每个案例在生成时已经拥有稳定的 `stem`，格式为 `case-<hash>`。当前三个聚合页只输出加粗人物信息，没有使用该 `stem` 生成链接。

## 实现设计

改动集中在 `scripts/build_cases.py`。聚合数据在保留现有展示文本和评价内容的同时，也携带案例的 `stem`。生成 Markdown 列表项时，将人物信息渲染为“加粗的 Markdown 链接”。

路径按聚合页所在目录生成：

- `docs/cases/by-university.md` 与 `docs/cases/by-major.md` 位于案例目录内，使用 `case-<hash>/`；
- `docs/experience.md` 位于 `docs/` 根目录，使用 `cases/case-<hash>/`。

链接直接来自当前案例对象，不通过昵称、院校或专业反向查找，因此同名投稿以及匿名投稿不会产生歧义。

生成后的展示形式保持不变：

```markdown
- [**Zrain | 软件工程**](case-xxxx/)：院校评价正文
```

“查看经验”页面使用相同结构，但链接带 `cases/` 前缀。

## 数据流

1. 投稿数据生成案例对象及稳定 `stem`。
2. 案例对象进入院校、专业和经验聚合逻辑。
3. 聚合项保留展示文本、评价正文和 `stem`。
4. 页面生成器根据页面位置构造相对链接。
5. MkDocs 将 Markdown 链接转换为站内案例详情链接。

## 边界与错误处理

- 没有可展示评价的聚合项仍按现有规则跳过。
- 某个院校或专业没有任何可展示评价时仍输出 `NULL`，不创建链接。
- 案例 `stem` 使用现有稳定生成规则，本功能不改变案例 URL。
- 不新增 JavaScript，不修改 MkDocs 路由或部署配置。

## 测试与验收

采用测试先行：先添加会因当前缺少链接而失败的生成器测试，再实现最小改动使其通过。

验收包括：

- 自动测试确认三个聚合页的人物信息都链接到正确案例；
- 确认评价正文不在链接范围内；
- 重新运行生成器并检查生成文件；
- 运行现有测试和 `mkdocs build --strict`；
- 在本地站点分别打开三个聚合页，点击人物信息，确认进入对应案例详情页且浏览器控制台没有新增错误。

## 不在本次范围内

- 不让整条评价或整行列表项可点击；
- 不改变案例详情页布局；
- 不调整聚合页排序、筛选或样式；
- 不修改发布流程。
