# “按院校”和“按专业”拼音排序设计

## 目标

让生成后的“按院校”和“按专业”聚合页按照完整院校名、专业名的汉语拼音升序排列，使页面实际顺序与现有“按拼音排序”说明一致。

## 当前问题

`scripts/build_cases.py` 当前对院校名和专业名直接调用 Python `sorted()`。该方法按 Unicode 码点比较中文字符，因此截图中的“上海交通大学、中山大学、北京航空航天大学”等顺序并非拼音顺序。

## 排序规则

- 使用名称的完整无声调拼音作为第一排序键。
- 排序时忽略拉丁字母大小写。
- 拼音完全相同时，使用原名称的小写化结果作为第二排序键，保证输出确定且稳定。
- 名称中的拉丁字母、数字、空格和括号等非汉字字符由拼音转换库保留，并参与完整名称的后续比较。
- 只调整聚合标题的顺序；每个标题下已有案例条目的顺序保持不变。

## 实现方案

在 `scripts/build_cases.py` 中引入 `pypinyin`，新增一个职责单一的 `pinyin_sort_key(name)` 辅助函数。该函数通过 `lazy_pinyin` 生成无声调音节，拼接并小写化后返回排序键，同时附带原名称的小写化结果作为兜底键。

生成 `docs/cases/by-university.md` 和 `docs/cases/by-major.md` 时，分别用该辅助函数排序 `uni_map` 和 `major_map` 的键。其他页面的排序逻辑不变。

项目的本地安装说明和 GitHub Pages 构建工作流都增加 `pypinyin`，确保本地与 CI 使用相同实现。

## 测试与验收

先在现有构建脚本集成测试中加入会暴露 Unicode 码点排序问题的数据，再运行测试确认其因顺序不符而失败。测试应同时断言：

- “按院校”标题按完整名称拼音升序排列；
- “按专业”标题按完整名称拼音升序排列；
- 名称含括号时仍按完整名称生成确定顺序；
- 两个页面原有链接、评价数量与文案行为不受影响。

实现后重新运行目标测试、完整测试套件和 `mkdocs build --strict`，再重新生成已提交的聚合页面。院校页开头应符合“北京……、电子……、复旦……、哈尔滨……”等拼音顺序，专业页同理按完整专业名拼音排列。

## 非目标

- 不改变“所有案例”“查看经验”或“学长学姐说”的排序。
- 不重新排序同一院校或专业下的案例条目。
- 不增加按拼音首字母分组、索引或前端交互。
